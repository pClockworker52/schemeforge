1. The idea

Proof-search systems work because a proof checker like Lean is a cheap and strict judge: an AI can try many ideas and the wrong ones fail fast. schemeforge asks whether exact solutions of flow problems can play the same role for numerical methods. If the judge is fast, exact and hard to fool, an LLM can propose code for a scheme component (a slope limiter, a flux), the judge scores it, and an evolutionary loop keeps the good ones.

The first arena is 1D compressible flow: shock tubes (Riemann problems) and the steady Laval nozzle with a normal shock. Both have exact solutions and run in milliseconds.

The first target, Target A, is a known gap. Sharp limiters (superbee, MC, Koren) give thin shocks and contacts but stall in steady nozzle runs: the residual stops dropping and Newton does not converge. Smooth limiters (van Albada, minmod) converge but smear discontinuities by 1–6 extra cells. No standard limiter has both properties. Target A asks for one that does, measured on held-out cases with pre-registered thresholds.

2. How it works

Every idea passes through the same pipeline. The colour shows what actually ran as the plan describes and what the main session did by hand instead.

StageWhat it does
HunchA written, falsifiable idea: mechanism, predicted metric change and a kill criterion, registered in the ledger before any test.
Proposer / engineAn LLM writes the candidate as a pure Python function. The engine (sforge evolve) mutates and crosses candidates on "islands", one per hunch.
SandboxStatic checks: only jax.numpy and math, no I/O, no hidden state.
JudgeRuns the candidate inside the project's own solvers. Smoke (seconds), dev (12 visible cases, ~26 s) and promo (65 held-out instances drawn from a secret seed; agents see only aggregates).
ArchiveKeeps the best candidate per "behaviour cell" (how compressive, how smooth) plus the Pareto set, and picks parents from them.
PromotionTarget A thresholds plus paired bootstrap tests against the best standard limiter on held-out data.
Breaker, analyst, refereeAgents that look for failure cases, explain a winner, check the literature and judge novelty.

4. What the search found

Round 1: stateless limiters φ(r), 4 hunches, 48 engine children

Three hunches refuted, one inconclusive. Smoothing the kinks of superbee or MC does not stop the stall. The best child, c-44f8015f87, is a smooth limiter (2r below r = 1, capped by a tanh curve above). It converges with Newton everywhere and is sharper than van Leer, but converges explicitly on only 60 % of held-out nozzles. It sits between van Leer and Koren on the existing trade-off curve, not beyond it. Label: variant of the superbee/MC family.

Round 2: limiters with memory (paused at generation 11 of 20)

The new limiter_stateful slot lets a limiter keep one value per cell between pseudo-time steps. The useful finding came from a failure: freezing φ itself is unstable, while freezing the centred factor ψ = 2φ/(1+r) is stable. A one-way "ratchet" on ψ after 1,000 steps (c-a84758f0e8) converges explicitly on all 20 held-out nozzles. Label: variant of limiter freezing (Venkatakrishnan 1995).

7 of 10 checks pass. The convergence half of the gap, the practically painful half, is closed for this limiter. Sharpness is not, and the memory mechanism cannot help there by design: it only acts after 1,000 pseudo-time steps, and unsteady runs are shorter. The remaining gap sits in the stateless base limiter, where round 1 already failed.

5. Does the approach make sense?

It helps to split the project's thesis into three separate claims. They have very different amounts of evidence.

A strict judge can be built cheaply

Supported. Audited exact solutions, held-out families, a red team that found real holes, a promotion test, all in about a day. The judge caught both cheating and dev-set over-fitting. This part would be worth publishing as a benchmark even if nothing else works.

An LLM swarm searches better than a person would

Not tested yet. All 10 hunches were written by the main session; proposals were mostly parameter sweeps; engine children mostly landed back on their seeds. The one engine improvement came from a "wild" mutation, and the best idea of the project (ratchet on ψ) came from reasoning about a failed run. So far this is an LLM-assisted parameter study, which is useful but not the thesis.

Target A has room for a new limiter

Doubtful in this slot. A φ(r) limiter is a one-variable function inside Sweby's TVD region, studied for 40 years. Target A also asks for Koren-level sharpness (A1) with van Leer-level overshoot (A7); on held-out data the sharp limiters overshoot 3–5 times more than van Leer (p90). That pair may be close to contradictory for any φ(r). This is a hypothesis worth one cheap check, not a result.

On practical value: limiter freezing is already common in production CFD codes (SU2, for example, has a setting for it), so a "variant of freezing" is an honest but modest outcome. A smooth, sharp limiter that converges with Newton and can be dropped into OpenFOAM would matter more. That is still the right goal, but sharpness probably has to come from a richer slot than φ(r).
