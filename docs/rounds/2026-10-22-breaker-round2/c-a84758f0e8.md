I found six cases where the candidate does clearly worse. Two of them show a flaw specific to the ratchet: no zoo member fails them, while the candidate drops to about first order or worse. All of them are in quarantine for Peter. I didn't edit the candidate or any judge code. Every run is suite dev, slot limiter_stateful, judge euler1d-v1.3.

**Mechanism.** The judge's `slope_ratio` returns r = 0 wherever the next difference is exactly zero, which is every cell of an undisturbed constant state. The base limiter gives phi = 0 there, so psi = 0. At step 1000 the ratchet records psi = 0 in all those cells and in any cell where r ≤ 0 (an extremum). Because psi can only decrease afterwards, any wave that reaches those cells later is computed first order for the rest of the run. In a periodic smooth flow, every cell hosts an extremum once per period, so the whole grid becomes first order within one period after step 1000.

- **Shared with the frozen zoo members:** superbee_frozen and van_leer_frozen also store psi = 0 in constant regions.
- **Candidate only:** frozen members never lower psi after step 1000, so they don't degrade in smooth flow.

## Verdict
- **Candidate-specific weaknesses:**
  - **B-0001 and B-0002:** smooth flow longer than 1000 steps falls to first order or worse; all six zoo members stay second order, superbee aside.
  - **B-0005:** an explicit-solver stall that five of six zoo members don't have.
- **Weaknesses of the freezing approach:** B-0003, B-0004 and the milder B-0006. The two frozen zoo members fail them too, but the non-frozen members don't, and the candidate is the worst or second worst in every one.
- **No case breaks all zoo members**, so none of these is a hard case.

The underlying design flaw: once 1000 steps have passed, any cell that has ever had r ≤ 0, including every constant-state cell at step 1000, stays first order until the run ends. Long unsteady runs and long transients in promo will expose it.

One side observation, not a case: the candidate's mirror_err on R1 is 0.0188, against about 1e-15 for the zoo (for example r-20261022-102434-25d5). The likely cause is the tanh-cap base limiter, which isn't symmetric (phi(r) ≠ r·phi(1/r)).
